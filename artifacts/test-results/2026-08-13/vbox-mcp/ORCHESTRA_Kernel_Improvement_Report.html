1. Executive verdict

Primary issue: With SCX_OPS_SWITCH_PARTIAL, Stage 8 showed enqueue=0 and run=0 while dispatch kept climbing. That means many “ORCHESTRA” benchmark labels may describe a loaded sched_ext ops object whose busy-loop workers were still largely on CFS — plus idle/dispatch callback noise — not full policy control.

Secondary issues are real but secondary: enqueue hot-path cost (map lookups, identity, controller gate, task-map writes), incomplete MIGRATE/SLEEP/THROTTLE semantics, and a no-op .dispatch hook that inflates counters.

Fix order: (1) prove task ownership, (2) fast-path enqueue, (3) real action semantics, (4) honest harness metrics, (5) bare-metal statistics.

3. Findings & fix locations

P0 Partial switching — workloads may not be on ORCHESTRA

Why: Ops are registered with partial switch. Enqueue/run telemetry did not advance under load while dispatch did — consistent with idle/balance callbacks without worker ownership.

Where:

kernel/sched_ext/orchestra_scx_stage7.bpf.c (SCX_OPS_DEFINE … .flags = SCX_OPS_SWITCH_PARTIAL) 

SCX_OPS_DEFINE(orchestra_sched_ops,
    ...
    .flags       = SCX_OPS_SWITCH_PARTIAL,
    .name        = "orchestra_scx_stage7",
    .timeout_ms  = 30000U);

What to change:

  • For controlled experiments: either carefully evaluate full switch, or explicitly move worker PIDs into the sched_ext class.
  • Gate every “ORCHESTRA” benchmark on rising enqueue_count / task_enable_count (or equivalent ownership proof).
  • Use .running / .enable hooks for per-task ownership traces (currently empty / light).

P0 Enqueue hot path does too much on every scheduling event

Why: Prior VM studies (~+20% vs CFS on short CPU jobs) and higher ctxt activity under ORCHESTRA align with BPF callback + map lookup cost.

Where: kernel/sched_ext/orchestra_scx_stage7.bpf.c → orchestra_sched_enqueue()

Current path always performs telemetry, active-directive read, identity check, controller gate, action switch, and bridge_record_task() map write.

What to change:

  • Fast-path default RUN when no directive / identity miss already falls back — skip task-map writes when not required.
  • Cache last accepted directive generation in BPF global/per-CPU state; skip full re-parse when unchanged.
  • Sample non-critical bookkeeping; keep fail-closed identity checks.
  • Profile with bpftool prog profile / perf after ownership is proven.

P1 Canonical actions are incomplete

Why: Research fidelity requires true MIGRATE / SLEEP / THROTTLE semantics; today’s implementations are approximations.

P1 .dispatch is a counter-only stub

Why: Inflates “dispatch” as a success metric without consuming DSQs or implementing balance policy.

Where: kernel/sched_ext/orchestra_scx_stage7.bpf.c → orchestra_sched_dispatch() 

void BPF_STRUCT_OPS(orchestra_sched_dispatch, s32 cpu,
                    struct task_struct *prev)
{
    struct bridge_telemetry *t = tel();
    if (t) tel_inc(&t->dispatch_count);
    /* Stage 7: dispatch is handled in enqueue via scx_bpf_dispatch */
}

What to change: Implement real consume/balance, or split telemetry into idle-dispatch vs enqueue-driven dispatch so reports stay honest.

P1 Bridge / control-plane fragility

Why: Maps must be re-pinned after every load; reload races caused “File exists” pin failures in this campaign. Controller lives in userspace; BPF only gates — so benches without published directives to worker PIDs do not exercise adaptive policy.

Where:

kernel/sched_ext/bridge/orchestra_bridge.c kernel/sched_ext/include/orchestra_bridge_v1.h load/unload scripts under kernel/sched_ext/scripts/ and benchmarks/real-machine/

What to change:

  • Auto-pin helper after struct_ops register.
  • Benchmark protocol: publish RUN/YIELD/THROTTLE to worker PIDs, verify via bridge status + telemetry.
  • Later (WP2): integrity/freshness if maps cross trust boundaries.

5. Harness defects (blocking science, not BPF logic)

  1. benchmarks/real-machine/benchmark_suite.sh — wait $(jobs -p) hangs on background scx_simple.
  2. Context switches read from cumulative /proc/stat — not per-run deltas.
  3. Fixed-duration busy loops → wall time ≈ duration for all schedulers.
  4. kernel/sched_ext/scripts/stage8_validate.sh — set -e aborts on rejected invalid PID; multicore helper used invalid bash volatile.
Preferred workloads after P0 ownership fix: yield-throughput (sched_yield), completion-time jobs, and wakeup-latency (nanosleep excess — matching the earlier Angle 1–3 methodology in docs/final_report/14_BENCHMARK_RESULTS.md.

6. Definition of “improved”

A kernel change counts as improved only when all of the following hold:

  • Ownership gate: ORCHESTRA runs show non-zero enqueue/run (or enable) under the workload.
  • Action contracts for RUN / YIELD / MIGRATE / THROTTLE / SLEEP are documented and tested at kernel semantics.
  • Hot-path cost is measured with ownership proven (not VBox busy-loop wall time alone).
  • Harness reports per-run metrics; stock scx hang is fixed.
  • Claims remain labeled by maturity class (VirtualBox vs bare-metal).
