Bottom line. The kernel supports sched_ext and the fresh ORCHESTRA object built, verified, attached, ran action telemetry, and unloaded safely three times. RUN, YIELD, MIGRATE, and THROTTLE produced scoped positive evidence. The finite positive workload timed out with no captured per-task accepted/dispatched record, so ownership and forward progress were not proven. No performance-superiority or general stability claim is valid.

What passed

Host, build, and verifier

  • Running-kernel sched_ext and required BPF/BTF configuration gates passed.
  • make clean, make, make check, and make test returned zero; the named userspace/reference suite reported 30/30 passes.
  • Fresh BPF object, bridge, loader, and fixed workload compiled out of tree with no source edits.
  • The loader reached verifier/relocation/registration successfully; no verifier rejection occurred.

Runtime and recovery

  • ORCHESTRA became the active sched_ext scheduler on three attach attempts.
  • All three unloads returned normally; final state is disabled and ORCHESTRA pins are absent.
  • No campaign-correlated ORCHESTRA oops, panic, lockup, RCU stall, hung task, verifier error, or scheduler error was observed.
  • CFS smoke completed CPU, memory, I/O, and mixed phases without workload errors.

Priority findings

P1 · INCONCLUSIVE

Finite positive ownership and forward progress not proven

The publication command returned an identity/generation, but the immediate exact-task status had zero accepted/dispatched counters and the worker did not finish within 20 seconds. No kernel error accompanied the timeout. The next experiment must wait for positive per-task enable/enqueue/running evidence before starting the timer.

Evidence: finite ORCHESTRA run · matched CFS diagnostic · full diagnosis

P2 · BLOCKED

Comparison and stress cannot be claimed

Missing optional tools, unsafe path/cleanup assumptions, and absent workload opt-in make the existing comparison and ORCHESTRA stress paths invalid on this host. The CFS smoke is useful as a host baseline only.

Evidence: tool availability · CFS stress smoke

P2 · NOT IMPLEMENTED

Architecture exceeds the current kernel prototype

Signal authentication, prediction, coordination metrics, feedback control, full hybrid safety, NUMA policy, and distributed scheduling remain specification/userspace scope. They are not real-machine kernel results.

Why no speed claim

  • The finite ORCHESTRA run did not complete within 20 seconds.
  • Its per-task ownership was not proven at the captured status point.
  • perf and scx_simple were unavailable.
  • Existing comparison scripts were unsafe for this machine without source changes.
Conclusion: the evidence supports loadability and scoped action behavior, not faster/slower/better scheduling.

What can and cannot be claimed

Supported by this campaign
  • Stage-7 BPF object builds against the running kernel BTF.
  • ORCHESTRA can register as sched_ext and unload safely.
  • Scoped RUN/YIELD/MIGRATE telemetry and THROTTLE/SLEEP paths are observable.
  • The tested positive long-lived task produced effective action counters.
Not supported by this campaign
  • Faster, better, or lower-overhead scheduling.
  • General single- or multi-worker forward progress.
  • Long-duration stability, fairness, scalability, or deployment readiness.
  • Kernel predictive coordination, cryptographic signal integrity, S1/S2/S3/S4/Q, controller, full RT safety, NUMA, or distributed claims.

Recommended next experiment

Run one exact-TID ownership retest using an existing safe protocol that waits for positive per-task enable/enqueue/running telemetry before timing a shorter fixed-work run. Compare with the already captured 5,036-ms CFS diagnostic. If the exact record again remains at zero, stop and investigate the admission/enqueue lifecycle before any performance or stress escalation.
